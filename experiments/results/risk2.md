## 채택

**방식 3 (대문자 단어 플레이스홀더).**

## 근거

세 방식의 차이가 극단적이라 판단에 여지가 없다. 방식 3은 13개 용어를 하나도 놓치지 않았고,
부수적으로 **번역 품질 자체도 방식 1보다 나았다.** 용어가 통째로 빠지면서 문장이 붕괴하던
케이스(`git commit 하고 push 해주세요`)가 방식 3에서는 `git commit AND push.`로 정상 복원됐다.

용어를 플레이스홀더로 치환하면 모델이 그 자리를 "번역할 수 없는 고유명사 한 덩어리"로 처리하고,
남은 한국어만 번역하게 된다. 결과적으로 용어 보호와 번역 품질이 동시에 개선된다.

## 관찰된 실패 양상

### 방식 1 (아무것도 안 함) — 용어가 음차되거나 문장이 붕괴

모델이 영어 용어를 "번역 대상"으로 오인해 소리 나는 대로 다시 쓴다.

| 입력 용어 | 출력 |
|---|---|
| `debounce` | `devounce` |
| `Vue` | `Viu` |
| `REST API` | `ReST APl` (소문자 L) |
| `TypeScript` | `Type Type Type Type` (반복 붕괴) |
| `git commit` / `push` | `Let's do it. Let's do it. Let's do it.` (문장 전체 소실) |

살아남은 4개는 `npm install`, `Docker`, `PostgreSQL` 정도로, **모델이 학습 중에 자주 본 흔한
고유명사만 버틴다.** 우리가 보호하려는 건 정확히 그 반대쪽(덜 알려진 라이브러리명)이라
이 방식은 쓸 수 없다.

### 방식 2 (특수문자 ⟦0⟧) — 모델이 기호를 무시한다

**0%다.** 남은 숫자만 번역돼 `zero`, `one`이라는 영어 단어로 출력됐다.

> **⚠️ 원인 정정 (2026-07-23, risk2b 실험 결과 반영):** 처음엔 "어휘에 `⟦`가 없어 unknown으로
> 떨어진다"고 적었으나 **틀렸다.** 토크나이저 진단 결과 `⟦0⟧` → `['▁', '⟦', '0', '⟧']`로,
> UNK 토큰이 아니다. 어휘에는 있으나 **학습 코퍼스에 거의 등장하지 않아 모델이 무시한다.**
> 상세: `risk2b.md`

```
"⟦0⟧ ⟦1⟧ 써서 처리했어요"  →  "I've taken care of it."          (표식이 통째로 소실)
"⟦0⟧ ⟦1⟧ 훅을 사용합니다"   →  "Use zero zero zero-one hook."    (숫자가 영어로 번역됨)
"⟦0⟧ 응답이 느려요"         →  "No, no, no, ... (38회 반복)"      (반복 붕괴)
```

> **교훈:** 플레이스홀더는 "모델이 모르는 기호"가 아니라 **"모델이 아는 단어"**여야 한다.
> 학습에서 못 본 토큰은 보호되는 게 아니라 그냥 무시된다.

### 방식 3 (TERMZERO) — 통과. 단 부작용 있음

용어는 100% 복원되지만 **주변 단어가 대문자화되는 경향**이 있다.

```
"npm install 먼저 실행하세요"   →  "npm install FIRST."
"git commit 하고 push 해주세요" →  "git commit AND push."
```

모델이 전부 대문자인 플레이스홀더를 보고 문맥을 약어/제목처럼 판단하는 것으로 보인다.
의미는 보존되므로 이번 범위에서는 문제 삼지 않는다.

> **후속 측정 완료 (risk2b):** "대문자가 아닌 형태(`Termzero`)로 재측정할 가치가 있다"고
> 적었으나 **재보니 15.4%로 폭락했다.** 대문자는 부작용의 원인이 아니라 **생존의 조건**이다.
> 대문자화 부작용은 감수하고 가는 게 맞다.
