> **`Docker`(07·20)와 `TypeScript`(08·19)가 각각 두 번 나오는 건 의도한 것이다.** 담당자가 달라
> **같은 용어를 다른 사람이 어떻게 발음하는지** 비교할 수 있다. 발음 차이에서 생기는 오차를

> **용어 표기는 공식 표기를 따른다** — `GitHub`(H 대문자), `Python`(P 대문자).
> 이 표기가 그대로 용어집의 표준형이 되고 보정·번역 결과로 출력된다.

## ✏️ 수정할 때 지켜야 하는 것

### 문장만 다듬는 경우 (자연스럽게 읽히도록)

자유롭게 고쳐도 된다. 단 **용어의 표준형 표기는 건드리지 말 것.**

| | 예 |
|---|---|
| ✅ 좋음 | `kubectl 로 파드 상태를 확인했어요` → `kubectl 로 파드 상태 좀 봐줄래요?` |
| ❌ 안 됨 | `kubectl` → `큐브시티엘` (한글로 쓰면 정답지가 깨진다) |
| ❌ 안 됨 | `npm install` → `npm 인스톨` |

**문장에 용어가 등장하긴 해야 한다.** 정답 판정이 "전사 결과에 이 표준형 문자열이 살아있나"이기 때문이다.

### 용어 자체를 바꾸는 경우

`Vue` 대신 다른 걸 넣는 식이면 **`data/terms.yaml`도 같이 고쳐야 한다.** 두 곳이 어긋나면
hotwords 목록과 정답지가 달라져 실험이 무의미해진다.

바꿀 때 확인할 것:

1. `data/terms.yaml`에 그 용어가 `canonical`로 있는가 (없으면 추가 + `aliases` 추측 작성)
2. 용어 수가 **20개 이상**인가 (`tests/test_terms_yaml.py`가 검사)
3. 한 용어의 `alias`가 다른 용어의 `canonical`과 겹치지 않는가 (같은 테스트가 검사)

고친 뒤 `uv run --extra dev pytest tests/test_terms_yaml.py -v`로 확인하면 된다.

### 다 고쳤으면

실험 담당자에게 알려주면 `manifest.yaml`을 다시 만들고 실험 스크립트를 돌린다.

## 읽는 법 (결과를 좌우한다)

- **평소 대화하듯 자연스럽게.** 영어 용어를 또박또박 원어민처럼 발음하면 실험이 무의미해진다.
  재려는 건 "한국인 개발자가 평소처럼 말했을 때 STT가 뭘 뱉는가"다
- 앞뒤로 1초 정도 여유를 두고 시작·종료
- 발음이 꼬이면 다시 녹음. 다만 **"정확하게 발음하려고" 애쓰지는 말 것**
- **한 사람이 다 읽지 않는다.** 화자가 한 명이면 그 사람 발음에만 맞춘 결과가 나온다
